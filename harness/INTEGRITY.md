# Future isolated-runner integrity protocol (design, not implemented)

The current CLI is a trusted-code local functional tool. Its sanitized workspace and public tests are not a secure competition environment. Before accepting untrusted submissions or publishing comparative model scores, implement and audit the following separate service.

1. **Freeze experiment identity.** Assign immutable task version, prompt digest, baseline tree digest, candidate patch digest, model/provider revision, agent configuration, seed, token/cost/time budgets, tool permissions, and evaluator image digest. Difficulty tiers here are provisional designer estimates, not empirically calibrated ratings.
2. **Separate environments.** Agent gets only baseline, instructions, and explicitly public feedback. Private evaluator source and references live on a separate host/service with no shared mount, user identity, network route, or readable credentials. Public fixtures here can remain smoke tests, but cannot later be relabeled secret.
3. **Use a hardened ephemeral VM/container runner.** Prefer defense-in-depth VM isolation for hostile workloads; run as unprivileged UID, drop capabilities, block host sockets and network, use readonly root filesystem and bounded writable scratch. Enforce CPU, memory, process, file-size, inode, wall-time, output, and total disk quotas outside the candidate process. Reap all descendants at the supervisor/cgroup boundary, including reparented processes. Destroy the runner after each submission.
4. **Freeze build inputs.** Resolve dependencies ahead of time from a pinned allowlist and image; never let candidate build scripts download code. Compile a source allowlist; do not reuse candidate build outputs. Mount evaluator code read-only and prevent candidate substitution of verifier classes or evaluator dependencies. Even classpath separation is not a sufficient security boundary in one JVM.
5. **Keep trusted verdicts out of candidate output.** Treat stdout/stderr as untrusted logs only. A supervisor should compute signed/authenticated verdict records over a restricted protocol, independently observe test assertions, bind results to job/task/candidate digests, and reject replayed, duplicated, malformed, or missing records. Candidates must not be able to forge PASS lines or modify result artifacts. The present CLI's parsed lines explicitly do not meet this requirement.
6. **Measure validity before aggregate scoring.** Report infrastructure error, compile failure, timeout, output/resource limit, flaky result, and functional failure distinctly. Repeat bounded concurrency tests across documented seeds/schedules; never quietly retry only failed model submissions. Record all attempts and budget consumption. Preserve failed artifact/log evidence subject to retention policy.
7. **Calibrate and review.** Run known-good references, deliberately wrong baselines, and a diverse mutation suite against the *same frozen private evaluator*. Audit for hard-coded answers, test leakage, environmental dependencies, and false positives. Use enough independent tasks/runs for uncertainty estimates; keep public smoke success distinct from generalization or model capability claims.
8. **Publish an honest result packet.** Include task/license provenance, experiment identity, denominator, per-check outcomes, retry policy, raw bounded logs, calibration evidence, uncertainty, exclusions, and limitations. Release no secret fixture content until the benchmark is retired. No scores from the present three calibration baselines should be labeled model scores.

Acceptance condition for that future service: an independent adversarial audit shows candidate code cannot read private fixtures, modify trusted verifier/results, communicate externally, escape its resource/isolation boundary, or influence other jobs. This document is a plan, not evidence that those protections exist today.

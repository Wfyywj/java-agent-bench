# 实验协议 v0.1（计划与约束）

## 三种资产分开

1. `catalog/` 是完整场景设计，不因有一个机制实现就自动变成整题已完成。
2. `engineering/` 是各设计的可运行工程切片，以每题 manifest 的 implemented scope 为准。没有真实数据库/集群的切片不能证明数据库/集群能力。
3. `tasks/R*` 是验收内核机制预实验，不代表综合工程难度。

同一个原始题 ID 的不同实现切片不能混在一个分母中比较。实验锁定实现路径、manifest hash、commit、任务版本和实际环境。

## 公平对照

- model track：固定 runner、工具、skill、提示词、预算，变化模型精确版本。
- workflow/skill track：固定模型精确版本及任务，变化单一流程因素。
- 任务顺序按种子打乱，A/B 配对共享同一题/重复编号，运行环境每次重建。
- 相同 wall-time、调用次数/token 上限，或完整报告资源不等价。pass@k 不与 pass@1 混比。
- 原始结果不可变。基础设施失败可以单列，但不能事后只删除差结果。
- 未知费用记 null；包含失败重试、子代理、缓存写入、环境开销，不仅最终答案 token。

## 验收

- 标准题：全部关键业务不变量 + 必需回归通过才算 success。
- Review/诊断题：交付结构化事实、位置、证据和行动范围；用固定事实 oracle 与可执行反例验证。自由文本评分需要独立盲审，不能直接用关键字数量代替质量。
- 给定错误实现应被合规测试检出；模型测试不能通过修改业务实现或读取参考解提高检出率。
- 任何被测模型的“通过”声明都不是验收结果。

## 安全与泄漏

当前自检运行原创可信参考/缺陷代码；不提供对不可信代码的安全隔离。不要直接让任意模型提交在宿主机运行。

正式模型评测必须另建隔离执行器：只读验收、受限资源、禁外网/受控模型代理、无用户凭据、无宿主 socket、从干净基线应用补丁。公开仓库的答案和验证器可被看见，prepared workspace 只是不主动复制，不等于无法读取。保留评测集不得进入本公开仓库或网站。

## 难度校准与统计

青铜至王者是暂定设计标签。先跑多个有区分度的 baseline 与人工完成时间，再冻结分级。出现全满分、全零分或不稳定时先修题，不发布夸张排名。

报告任务级成功数/总数、重复次数、paired delta、按任务聚合的不确定性、失败类型和总成本；具体统计方法在正式样本计划冻结后确定。当前没有模型评测结果。

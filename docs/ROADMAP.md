# 建设路线与完成定义

## M0：可复现开发预览
- [x] 五段位各五个原创场景设计。
- [x] 三个可运行 Java 机制任务与参考解/错误修复验证。
- [x] 功能验收内核、结果 schema、单元回归。
- [x] 任务网站、实验计划导出和结果导入。
- [ ] GitHub 阶段成果同步，等待连接写权限验证。
- [ ] 网站实际部署与浏览器交互验收。

## M1：首批真实工程任务
按题族逐题实现，不把 25 个空工程当 25 个任务。
- 先 B02、S01、S04、G01、G05，每题提供固定基线、多文件修改、业务口径与独立验收。
- 引入 Maven/Spring/数据库时锁定版本与依赖；无法离线复现的任务不标 ready。
- 每题至少通过 reference/nop/多个近似错误解/重复运行四类门禁。
- 需求澄清和 Review 采用结构化交付、证据位置与明确错误事实；不让 LLM judge 独占主分。

## M2：五档可执行库
- 将剩余设计逐步实现，黄金以上必须体现跨服务/异步/事故/阶段演进约束，不只增加代码行数。
- 王者先提供多阶段工程状态与连续回归，再做故障恢复；没有这些资产就保持 design_only。
- 将每题支持范围、已知遗漏、来源、验收覆盖公开。

## M3：隔离模型实验
- 独立 agent/verifier 容器或 VM，禁止宿主 Docker socket 与密钥暴露。
- 提供固定 runner 与模型 adapter、不可变日志、预算/成本和取消。
- 用户明确模型端点、调用预算与授权后才跑付费模型。
- 先少量 pilot 确认天花板/地板/抖动，再执行正式配对实验。

## M4：持续发布
- 任务版本不可变；修改验收口径必须升版本，历史成绩不与新版本混排。
- 发布变更日志、失败分类与回归证据；真正模型结果与自检分区。
- 新题来源可追溯，外部项目代码按各自许可证处理。

每一阶段完成都需可验证产物；本文是计划，不代表已经部署持续自动执行服务。

## M1：工程切片与真实框架集成

已实现五档各五个有限范围的可运行工程切片；S04/S05 使用实际 H2 JDBC/SQL，仍不声称 PostgreSQL 或完整 Spring 验证。完整原设计保持 design_only。已增加真正 Spring 事务集成变体，H2 中验证实际事务代理与并发回滚；PostgreSQL/生产连接池与完整 HTTP 链路仍待实现。

B02、S01、S04、S04-spring、G01、G05 的四门证据在 `engineering/m1-gates/evidence/summary.json`。发现清单把这六条实现标为 `gates_green`。`full_catalog_ready` 仍为 false。S04-spring 仍是集成切片，H2 与连接池没有被标成就绪。

### 完整任务门禁
按题族逐题实现，不把 25 个空工程当 25 个任务。
- 先 B02、S01、S04、G01、G05，每题提供固定基线、多文件修改、业务口径与独立验收。
- 引入 Maven/Spring/数据库时锁定版本与依赖；无法离线复现的任务不标 ready。
- 每题至少通过 reference/nop/多个近似错误解/重复运行四类门禁。
- 需求澄清和 Review 采用结构化交付、证据位置与明确错误事实；不让 LLM judge 独占主分。

## 当前优先阶段：可信验收与离线实验闭环

详见 [阶段任务与验收标准](TRUSTWORTHY_EXPERIMENTS.md) 和 [合成 Recipe 操作说明](../experiment_tools/RECIPE.md)。优先修复业务漏检、源码/运行绑定、错误分类及受控进程清理；暂缓扩题。离线 Recipe 仅是明确标记的 B01 合成协议回放，不执行 Java 验收或模型，也未接通网站导入。真实试验必须完成 M3 前置条件。

## M2：五档可执行库（可信验收阶段之后）
- 将剩余设计逐步实现，黄金以上必须体现跨服务/异步/事故/阶段演进约束，不只增加代码行数。
- 王者先提供多阶段工程状态与连续回归，再做故障恢复；没有这些资产就保持 design_only。
- 将每题支持范围、已知遗漏、来源、验收覆盖公开。

## M3：隔离模型实验
- 独立 agent/verifier 容器或 VM，禁止宿主 Docker socket 与密钥暴露。
- 提供固定 runner 与模型 adapter、不可变日志、预算/成本和取消。
- 用户明确模型端点、调用预算与授权后才跑付费模型。
- 先少量 pilot 确认天花板/地板/抖动，再执行正式配对实验。

## M4：持续发布
- 任务版本不可变；修改验收口径必须升版本，历史成绩不与新版本混排。
- 发布变更日志、失败分类与回归证据；真正模型结果与自检分区。
- 新题来源可追溯，外部项目代码按各自许可证处理。

每一阶段完成都需可验证产物；本文是计划，不代表已经部署持续自动执行服务。

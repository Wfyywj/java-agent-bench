# M0 浏览器交互验收记录（2026-10-28）

对应 [issue #3](https://github.com/Wfyywj/java-agent-bench/issues/3)。这是真实 Chrome 里的点击、键盘、文件选择、下载和刷新记录。`node --test tests/test_web.mjs` 没有当作本记录的证据，也没有改判分、分析规则或数据协议。

## 结论

当前 **main 的本地预览通过** issue #3 的交互清单，包括桌面与 390px 宽度、任务详情三种关闭方式、实验计划真实下载、结果 JSON 的成功导入、坏 JSON、校验失败、重复导入，以及保存后刷新恢复。任务详情里的 #15 中文风险标签和「切片支持范围」列表在 main 上可读。

**公开站不是这份 main。** 页面没有嵌入 git SHA。公开站 `app.js` 更短，B01 详情仍把风险写成 `failureCases` / `traps` / `invariants` / `criticalFailurePolicy`，也没有「切片支持范围」标题。这是已关闭的 [#8](https://github.com/Wfyywj/java-agent-bench/issues/8) 尚未部署，不是 main 上的新缺陷。本记录不勾 `docs/ROADMAP.md`，也不关闭 #3：公开站仍落后，ROADMAP 勾选需要人确认。

## 方法与夹具

在 Chrome 里切换导航、打开对话框、按 Esc、点遮罩和关闭按钮、选择本地文件、接收下载，然后刷新。导入用的成功文件是仓库里已有的验收器自检，不是模型分数。

| 文件 | 用途 |
|---|---|
| `harness/results/R01-selfcheck.json` 的 `reference` | 合法单次结果。SHA-256 `884691176acef90838861f0015e29103381f403ed12b35d9634b340243a1e221`。R01 参考解自检，`schema_version` 1.0，`task_version` 1.0.1，`status` `passed`。页面把它标成「未认证」 |
| 同一文件的根对象 | 合法 JSON，但不是单次结果，用来触发校验失败 |
| [fixtures/truncated.json](fixtures/truncated.json) | 截断内容 `{"task_id": `，用来触发 JSON 解析失败 |
| [evidence/experiment-plan-main-desktop.json](evidence/experiment-plan-main-desktop.json) | 桌面 main 上实际下载的 `experiment-plan.json`。名称和模型 ID 是验收时填进表单的字，不是测量结果。`executable` 为 false，`cost_usd` 为 null |

仓库里没有已提交的 `schema_version: engineering-1.0` 结果文件（该形状由 `scripts/engineering.py` 在本地 evaluate 时写出）。因此工程切片结果导入没有用编造哈希去测。R 系列路径按站点声明测过。

### 实验计划导出

表单里的名称、对照、实验组、模型 ID、重复次数、预算和种子是验收输入，用来确认导出，不是模型成绩。

1. 空白导出
   - 步骤：打开「设计对照实验」，不填字段、不选任务，点「导出实验计划」。
   - 期望：不下载文件。字段本身不是占位默认值。
   - 实际：四个组合的字段全是空字符串。状态为「请至少选择一个任务。」没有下载。
   - 结果：通过。拒绝发生在空字段文案之前，因为还没有任务。
2. 已选任务但字段仍空（main 桌面补测）
   - 步骤：只勾选 B01-slice，其余留空，再导出。
   - 期望：拒绝，不下载。
   - 实际：「名称、对照组、实验组或模型仍是占位或未填写。占位文字不能当作模型、对照组或实验组的取值。」
   - 结果：通过。
   - 截图：[main-desktop-plan-blank-fields.png](../../artifacts/browser-acceptance/main-desktop-plan-blank-fields.png)
3. 旧占位符（#7 回归）

   - 期望：占位文字被拒绝，不下载。

   - 结果：通过。#7 在 main 和公开站都仍然挡住占位导出。

### 刷新恢复

存储键是 `jab-results-v1`。刷新后默认视图是任务实验室，要再打开「结果与证据」才看得到恢复文案。

1. 未保存就刷新
   - 步骤：导入 reference 后不点「保存全部到此浏览器」，刷新，再打开结果页。
   - 期望：记录消失，回到空态。页面在导入成功时已经提示未保存会丢失。
   - 实际：四个组合都是空态「等第一份真实结果。」，列表里没有 R01。
   - 结果：通过。
2. 保存后刷新
   - 步骤：再次导入，点「保存全部到此浏览器」，刷新，等目录计数变成 25，再打开结果页。
   - 期望：`已从此浏览器恢复 1 条未认证证据。` 且 R01 行还在。
   - 实际：main 桌面和移动通过。保存文案为「已保存 1 条到此浏览器；建议导出备份。」恢复文案与 R01 行符合期望。公开站在目录 JSON 尚未返回时立刻点进结果页，会先看到空态；等 `#total` 为 25 再进入，公开站桌面显示「已从此浏览器恢复 1 条未认证证据。」和同一条 R01。公开站移动宽度第一次截图与 main 的成功恢复画面字节相同。localStorage 在保存后的四个组合里都有这条数组。
   - 结果：通过。早先那次公开站空态是在目录加载完成前读的，不是产品把已保存记录弄丢。
   - 截图：[main 桌面](../../artifacts/browser-acceptance/main-desktop-reload-restored.png)、[main 移动](../../artifacts/browser-acceptance/main-mobile-reload-restored.png)、[公开站桌面确认](../../artifacts/browser-acceptance/public-desktop-reload-restored-confirmed.png)。

## 缺陷清单

没有在 main 上发现需要新开 issue 的交互缺陷。下面两项是公开站和 main 的差距，留给人决定是否重新部署。本记录不新开 issue，也不关闭旧 issue。

1. **公开站任务详情仍是 #8 修复前的渲染。** B01 风险区显示原始键名，没有「切片支持范围」。main `app.js` 已包含中文标签和切片范围。公开站 `app.js` SHA-256 是 `da30259b…`，main 是 `d008049b…`。重新部署当前 main 后，公开站应与本记录的 main 截图一致。

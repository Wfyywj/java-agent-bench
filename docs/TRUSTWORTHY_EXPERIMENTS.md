# 可信验收与可复现实验阶段

本阶段依据 [2026-10-28 能力实测](assessments/2026-10-28-capability-audit.md)，优先修复会影响结论的缺陷，而不是扩充题目数量。实现与验证状态以本阶段最终验证记录为准；本文先定义范围和验收标准。

## 目标与明确不做的事

1. 错误修复不能因为遗漏关键契约而得到绿灯。
2. 绿灯必须绑定当前源码与本次成功验证，不能继承旧版本证据。
3. 实验计划、槽位、原始证据与分析结果能通过一个有类型约束的离线流程复演。

本阶段不调用外部模型、不创建凭据、不花费模型预算，也不把参考解或合成回放称为模型成绩。不引入新任务、不发布排行榜、不宣称安全沙箱。真实 Codex CLI / Claude Code 运行仍需要隔离环境、明确配置、权限与预算。

## A：判卷器与门禁

### A1 业务验收反例

- B02：首次归还的器材必须属于借单，错误请求不得修改借单、事件或清洁任务；正常与损坏路径均覆盖，之后合法请求仍能成功。
- S01：两种方向的终态冲突都必须进入人工复核，保留原终态；重复回调、旧序号和重启后的状态分别验证。
- 两个审计中漏放的最小错误修改成为永久 mutant。基线继续失败，参考解继续通过，mutant 必须以明确的业务断言失败被检出。
- 加强验收后提升切片版本；不同 manifest 版本不能混合比较。

### A2 证据新鲜度

- 按内容计算确定性源码指纹，覆盖任务输入、验收器、变体和共享运行器；排除生成证据、缓存和构建产物，避免循环哈希。
- 每次运行有独立身份和结果；先登记本次运行，再执行测试。失败或中断不能让旧成功冒充本次结果。
- 历史证据保留。目录仅在当前指纹、最新运行身份和全部门禁一致时提升为 gates_green；旧格式/过期/未完成/失败均不得提升。
- 这是可复现性检查，不是数字签名或防恶意篡改机制。

### A3 失败分类与进程清理

- 业务断言失败与超时、启动失败、编译失败、报告缺失分别记录。非零退出码本身不等于 semantic kill。
- 运行器超时/取消后回收本次拥有的后代进程，包含脱离原进程组的子进程；测试只终止自身创建的进程。
- 本地监督器不是隔离边界；不保证对抗恶意代码，不能替代容器、VM 或独立 verifier。

## B：有明确边界的离线实验闭环

先实现合成回放，用来验证数据协议而不是测试模型。

- 冻结配置：明确任务版本、A/B 配置、重复次数、预算口径与槽位；已有计划不能静默覆盖。
- 独立工作区：每个槽位的候选和基线互不覆盖，不复制参考答案与验收器。
- 明确记录：计划、启动/回放状态、证据文件与哈希、取消/失败原因可追溯。未知费用和时间保持 null，不能补零。
- 严格分析：保留全部预定槽位与失败；缺失时报告不完整，不能只挑成功记录。版本或配置不匹配应拒绝。
- 数据隔离：synthetic 必须显式启用并贯穿输出；不接受把 reference/selfcheck 重新包装为 actual agent trial。
- 源码内容身份与运行产物身份分开，准备时间变化不应伪装成代码变化。

本阶段可以交付机器可读的结果接口，但不抢占正在协作的前端文件。网站直接导入新协议必须有独立验收，不能因为生成了 JSON 就声称 UI 已接通。

### 已实现的 B1：合成协议演练

在仓库根目录执行以下命令即可演练，不需要 CLI 登录、模型额度或 Java：

```sh
PARENT=$(mktemp -d)
python3 -m experiment_tools.recipe example > "$PARENT/recipe.json"
python3 -m experiment_tools.recipe freeze --recipe "$PARENT/recipe.json" --run "$PARENT/run" --allow-synthetic
python3 -m experiment_tools.recipe replay --run "$PARENT/run" --allow-synthetic
python3 -m experiment_tools.recipe analyze --run "$PARENT/run" --allow-synthetic
```

最后一步预期退出码为 **2**，不是程序崩溃：示例刻意包含 6 个预定槽位，其中 1 个缺失、1 个执行前取消，因此结果必须是 `incomplete`。4 条合成记录包含失败，时间/费用均为 null。查看 `$PARENT/run/analysis/report.json` 和 `display.json` 可核对完整槽位。同一次命令写出的 `display.json` 已按字节冻结在 [samples/synthetic-replay-display-1.0.md](samples/synthetic-replay-display-1.0.md)，只供前端审阅接口；本文件不表示 UI 已接通。

若要演练完整报告，在冻结前把示例的 `repeats` 改为 `[{"repeat":1,"A":"failure","B":"success"}]`，然后使用全新的运行目录。旧计划、回放和分析不能覆盖。详细协议见 [RECIPE.md](../experiment_tools/RECIPE.md)。

这一步产生的是工具编造并明确标记的**测试夹具断言**，不是实际 Java 验收输出。它验证准备、身份绑定和分析的数据链路，尚未完成“真实 CLI → 独立验收 → 网站结果”的 B2 闭环；实际调用、执行中取消/超时、真实证据导入和 UI 展示仍明确待办。

## 协作与交付

本侧负责业务反例、门禁、进程监督和离线协议。现有详情可读性工作位于另一个分支，避免同时修改 dist/app.js 和 tests/test_web.mjs。合并前重新核对远端，保护协作者改动。

每个实现提交应附针对性回归，最后运行全库离线检查、可信 Java 自检及重新生成的 M1 门禁。仅在具体提交的 CI 结束后报告 CI 结论。代码发布、公开站部署和真实模型试验分别报告，不互相替代。

## C：后续真实 pilot 的启动条件

本阶段不执行。启动前必须确认可丢弃隔离环境、精确 CLI/模型版本、认证来源、允许权限、总预算、超时/取消与计费策略。先做小样本可行性试验，再决定是否值得扩大；系统对比不能误标为模型单因素对比。
